## [0.18.0] - 2026-09-29 — Линия DSH 0.2.0-rc.1 (compat/0.2.0: чисто метаданная адаптация, ноль изменений кода)

### Добавлено
- **Реализация `captureWithinBudget` в render-воркере** (исправление блокировки на реальной машине в линии 0.2.0): `capture` в `bin/cdp-render-worker.mjs` вызывал до сих пор никогда не определённую функцию (capture-цепочка на реальной машине падала всегда, и это маскировалось гейт-пробой). Теперь реализована лестница качества JPEG (старт с 72, шаг 12, нижний предел 24, превышение бюджета честно сообщается как `overBudget`) + геометрическое уменьшение через `scale.maxWidth` + однострелочные пути для PNG/без бюджета; `data` возвращается в base64 для потребления цепочкой суждений JEV. Реальный тест: Chrome/153 реальное подключение, бюджет достигнут с первой попытки (attempt 1, q=72).
- **Включён полу-`noImplicitAny` у клиента**: `tsconfig.client.json` поднят до `noImplicitAny: true`, все 401 implicit-any сделаны явными (`scripts/fix-implicit-any.mjs` позиционно точный codemod + ручная доводка); аннотации типов не имеют нулевого эффекта на рантайм, `client-input.test.ts` досинхронизирован по regex на источниках.
- **Гейт-пробы включены на реальной машине**: remote-CDP проба (4/4) и render-проба (1/1) успешно пройдены против реального локального Chrome/153 — цикл discovery→attach→inspect→input→binding + цепочка скриншотов с бюджетом. cli-probe и login-import e2e остаются привязаны к vendored Linux-рантайму, гейты сохранены (на этой машине N/A).

## [0.8.4] - 2026-09-15 — Исправления цепочки запуска воркера окна наблюдения + слияния комьюнити-PR

### Исправлено
- **Окно наблюдения никогда не запускалось на DSH ≥ 0.1.5 (#34 / #38 / #43)**: у spawn воркера отсутствовал обязательный для subprocess provider 0.1.5 `cwd`, а исключение заглатывалось голым `catch`, из-за чего `ensureWorker()` всегда возвращал null. `cwd` добавлен.
- **Воркер убивал себя при запуске (дефект 2 из #34 / #40)**: свободное подстрочное сопоставление в `stopSiblingWorkers()` принимало subprocess runner DSH за воркера-пара, и `taskkill /T` заодно убивал собственное дерево процессов — воркер умирал, не успев записать `ego-cast.json`. - **На Windows EGO_LINUX_HEADLESS молча игнорировался (#35)**: явный `EGO_LINUX_HEADLESS=1` теперь имеет приоритет над выводимой по умолчанию `hasDisplay=true` win32, в согласии со справкой CLI / документацией README.

### Ограничения платформ
- Windows требует FFmpeg с `gfxcapture`; HWND сопоставляется по PID браузера, заголовку target и границам окна CDP; даже при перекрытии или перемещении окна целевая страница всё равно захватывается, а откат к `gdigrab desktop` запрещён. Поведение в свёрнутом окне по-прежнему решает Windows Graphics Capture.
- Linux X11 использует `x11grab`, macOS — `avfoundation` как кроп экрана; перекрытие и системные разрешения по-прежнему влияют на обе платформы.
- Wayland: если комплектный FFmpeg не имеет работоспособного ввода Portal/PipeWire — явная ошибка `unsupported-ffmpeg-pipewire`, без root-`kmsgrab`, без тихого переключения на весь рабочий стол и без имитации успеха.

### Исправлено
- **Мышь местами совсем без запросов / клавиатура постоянно не работает**: управляющая плоскость больше не зависит от `streamState` и синхронизации spaces, а отправляет только по target текущего изображения; воркер сохраняет финальную проверку устаревших целей. Раньше у фронтенда не было ни слушателей клавиатуры, ни поддержки протокола — весь путь text/keyDown/keyUp закрывается здесь.
- **FFmpeg реально работал, но вкладка показывала CDP**: состояние захвата теперь сводится единообразно из SSE, ответа watch, spaces capture и watch/status; при отсутствии бэкенда сохраняется текущее значение, перезапись по умолчанию на CDP запрещена.
- **Оставшаяся после `space_open` пустая about:blank**: успешно открытое пространство задач становится последним активным пространством; последующие инструменты без `space` (navigate/click/fill и др.) переиспользуют это пространство, вместо отката к фиксированному `dsh-agent` с созданием второго окна. После закрытия активного пространства восстанавливаются значения по умолчанию конфигурации.
- **watch/start 502 и input 500**: проба возможностей бинарника FFmpeg и `gfxcapture` переведена на асинхронный подпроцесс, здоровье воркера больше не блокируется во время старта; тайм-аут прокси воркера для watch start/switch поднят до 30 секунд, покрывая полный потолок окна, кодировщика и MP4-инициализации. host транслирует HTTP-статус воркера и JSON-ошибку как есть, и возвращает 502 только при реальной недостижимости воркера. Ввод валидируется на обеих сторонах, клиент и воркер; неверная цель возвращает 409 `capture-target-stale`, а не заворачивается в 500.
- **FFmpeg выбран в настройках, но вкладка всё ещё показывала CDP**: когда несколько волокон грузили плагин одновременно, позже зарегистрированный settings bridge при дубликате namespace ошибочно откатывался к пустой composition config, и cast worker получал `captureBackend:auto`. Теперь один и тот же сервис настроек делит единственный scope; карта настроек, шлюз и cast-server всегда читают одну и ту же персистированную конфигурацию. Воркер в простое, получив обновление конфигурации, немедленно публикует новое состояние бэкенда, не удерживая старый CDP-ярлык.
- **FFmpeg на Windows больше не снимает окно первого плана пользователя**: раньше параметры были жёсткими — `gdigrab ... -i desktop` — с кропом по координатам страницы только при старте, так что стоило Chrome уйти в фон, как DSH или другое приложение в зоне покрытия уходило в стрим. Теперь цель сначала резолвится в HWND через `Browser.getWindowForTarget` и перечисление топ-уровневых окон Win32, затем `gfxcapture` захватывает поверхность изолированного окна; разные окна Chrome разных пространств задач получают разные HWND. Фоновая вкладка того же окна сообщает `ffmpeg-target-not-visible`, не показывая чужую вкладку и не перехватывая фокус по своей инициативе.
- Кодирование Windows предпочитает аппаратный путь D3D11 у `h264_mf`; проба кодировщика использует реальный HWND-конвейер, чтобы тестовый программный кадр не объявлял ложно недоступным аппаратный кодер. Явные `fps/setpts` фиксируют 30 FPS, фрагментация fMP4 опускается до 100 мс, а `skip_trailer` избегает ошибки парсера `mfra` при корректной остановке.
- **Состояние входа переживает перезапуски DSH (верное философии оригинального ego-lite)**: раньше после ручного перезапуска / жёсткого убийства DSH требовался повторный вход — при SIGTERM/SIGINT воркер лишь отсоединялся, не записывая на диск, а 4-секундной грации `--stop` при выгрузке плагина не хватало, дело кончалось откатом SIGTERM-краха. Теперь перед своим уходом воркер шлёт браузеру CDP `Browser.close` (корректное закрытие, журнал cookie сливается в дисковый profile), а грация teardown плагина поднимается до 8 с — достаточно для полного корректного закрытия. **Проверено на практике**: после корректного перезапуска вход полностью сохраняется; и после жёсткого убийства (SIGKILL) долгоживущий статус входа записан на диск и читается при перезапуске.

### Инженерный рефактор
- **Миграция чистого JS → TypeScript (PR #14)**: исходники переезжают из `lib/` в `src/` (`src/index.ts` слой инструментов, `src/client/index.ts` фронтенд, `src/worker/ego-cast-worker.ts` воркер), `lib/` и `bin/ego-cast-worker.mjs` становятся артефактами сборки (предсобранные и закоммиченные). Цепочка сборки становится `pnpm typecheck` (типовой барьер tsc, tsconfig.json + tsconfig.client.json) + `pnpm test` (vitest) + `pnpm run build` (три бандла tsdown). Тесты параллельно переезжают из `tests/*.test.mjs` в `.test.ts` с добавлением `vitest.config.ts`. `lib/` больше не правится руками.

## [v0.8.0] - 2026-08

Интеграция вкладки sidebar: когда доступен `dsh-better-sidebar`, окно живого просмотра регистрируется как нативная вкладка sidebar, а не плавающее окно.

### Добавлено
- **Интеграция вкладки dsh-better-sidebar**: `apply()` оппортунистически разведывает сервис sidebar через `ctx.get('betterSidebar')` (не `ctx.betterSidebar` — тот требовал объявления `inject`, делал sidebar жёсткой зависимостью и без него не дал бы загрузиться всему плагину вместе с картой настроек); при доступности регистрирует через `registerTab()` вкладку `ego-browser:watch` (`single: true`, резидентная), иначе откат к прежнему плавающему окну. Это документированный шаблон потребления опциональных сервисов в DSH (см. заметку approval-seam, postmortem 0001).
- **Автооткрытие вкладки при первом вызове инструмента `ego_*`**: пути execute `defineEgoTool` / `ego_cli` / `ego_captcha` / `ego_script` вызывают `markEgoToolCall()`, наращивая счётчик на стороне host, который рассылается с ответом `/api/ego/spaces`. `LivePreviewController`, заметив скачок 0 → >0, вызывает `ctx.get('betterSidebar').openTab({ type: 'ego-browser:watch' })`, вкладка раскрывается автоматически. Флаг `autoOpened` гарантирует одно открытие на сессию.
- **React-компонент вкладки `EgoBrowserTab`**: рендерит содержимое вкладки sidebar через `React.createElement` + `bindSnapshotSelector` (шапка / панель вкладок / живой главный вид / слой истории / полосы подсказок login и captcha). Трасса навигации переходит с бокового ящика на наложенный слой (кнопка истории занимает всю область содержимого вкладки, клик по записи входит в предпросмотр или возвращается к живому), адаптировано к узкой ширине sidebar.

Контроллер держит ref `<img>` напрямую, заменяя `src` на месте с частотой слияния rAF, не заставляя React перерендериваться каждый кадр.

### Дизайн-развязки (сказано честно)
- **Гибрид, а не полная переработка**: React отвечает за структуру UI (шапка / вкладки / полосы подсказок / слой истории), vanilla-контроллер — за конвейер кадров реального времени (SSE / слияние rAF / обратное отображение координат / пересылка ввода). Около 1000 строк хрупкой стриминговой логики не переписаны в React-хуки — ради снижения риска регрессий.
- **История как наложенный слой**: боковой ящик плавающего окна давал две узкие колонки при узкой ширине sidebar (~300-400 px); наложенный слой использует пространство лучше всего.
- **Гонка (известна, принята)**: если `dsh-better-sidebar` загружается после ego-browser, `ctx.betterSidebar` может быть ещё `undefined` в момент работы `apply()`, и происходит откат к плавающему окну. Загрузчик модулей DSH обычно грузит в порядке зависимостей, а sidebar как базовый UI-плагин грузится первым; иначе достаточно обновить страницу.
- **Код плавающего окна сохранён как есть**: `mountFloatingWatch()` — механический перенос тела старого effect без изменений логики, гарантирующий без sidebar опыт, полностью совпадающий с 0.7.x.

- **Управление памятью фронтенда**: `frameCache` окна наблюдения (последний JPEG dataURL каждой вкладки) и `pageMeta` накапливались без границ по `targetId` — медленная течь на длинных сессиях/множестве вкладок. Теперь кэш закрытых вкладок обрезается по таблице живых вкладок, а `frameCache` получает страховочный потолок `MAX_CACHED_FRAMES=12` с приоритетом самых старых.
- **Захардкоженный откат домашнего каталога `/root` заменён на `os.homedir()`**: в разведке путей состояния стандартный POSIX-дом от независимого `/root` меняется на кроссплатформенно верный `os.homedir()`, устраняя ловушку для окружений без root/контейнеров.

### Инженерия
- Новое `.gitattributes`: унифицированные переводы строк LF (`* text=auto eol=lf`), устраняя CRLF-дрожь рабочего дерева из-за `core.autocrlf` на Windows и ложные срабатывания diff/cp.

## [v0.6.1] - 2026-04

Исправляющая версия: цепочка самолечения + стабильность воркера окна наблюдения, юзабилити полосы онбординга панели.

### Исправлено
- **Удаление плагина больше не блокирует выход хоста / не ломает самолечение**: teardown в `ctx.effect` переходит от `await ego-browser --stop` (15 с грации, задерживавших выход хоста) к fire-and-forget — хост может быть чисто поднят `dsh-web-guard` за 10 с, а прерванный turn автоматически продолжен.
- **Guard одиночного экземпляра воркера окна наблюдения + очистка устаревших состояний**: один и тот же `ego-cast-worker.mjs` мог запуститься одновременно из каталога установки и из dev-клона, а `ensureWorker` поднимал ещё один при известной мёртвой pid — `ego-cast.json` постоянно указывал на мёртвого/отстающего воркера, и панель теряла стрим. Теперь при старте воркер перечисляет и останавливает другие одноимённые процессы (на Windows через `powershell -EncodedCommand`, на POSIX через `ps`), удаляет устаревший `ego-cast.json`, делая свой `{port,pid}` единственной инстанцией авторитета.
- **Полосы онбординга login/капчи закрываются вручную**: добавлена кнопка ×; обе полосы показываются во взаимном исключении (капча приоритетна), больше нет «не закрыть» и «двойная полоса сжимает картинку».
- **Окно наблюдения активно следует за страницей, на которой работает агент**: раньше панель брала «последнюю перерисовку» (lastActive) за текущую страницу, перерисовки фоновых страниц анимации/видео крали вид, и главный экран не прыгал при смене страницы агентом. Теперь воркер через DevTools `/json/list` получает MRU-активную вкладку браузера (то же суждение, что в `tabs.mjs` рантайма ego), помечает её `active: true` и ставит первой в `/api/spaces` как и в SSE; автослежение фронтенда следует только за активной страницей, игнорируя кадры фоновых перерисовок.
